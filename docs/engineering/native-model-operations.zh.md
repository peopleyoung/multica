# 内置模型配额与观测

API 持有唯一上游模型配置。执行、历史摘要、聊天标题和后续建议均经过 `pkg/llm` 的 HTTP 准入，每一次 SDK 重试或参数协商都会重新申请配额。没有通过准入的请求不会到达上游；数据库不可用时停止模型调用。

## 配额

所有 API 副本使用同一个 PostgreSQL 主库和相同的 `MULTICA_LLM_LIMITS_JSON`。默认配置如下，可只覆盖部分正数属性；无效配置会阻止 API 启动。

```json
{"global_concurrent":16,"workspace_concurrent":4,"global_requests_per_minute":600,"workspace_requests_per_minute":60,"global_tokens_per_minute":4000000,"workspace_tokens_per_minute":1000000}
```

并发、最近一分钟的请求数与 Token 预算由一个短事务串行检查并预留。模型调用期间不占用数据库连接。同一运行的执行和摘要不能并发申请；标题和后续建议按用途、会话隔离。

文本预留量使用请求字节数加输出 Token 上限。图片至少预留模型声明的整个上下文窗口。辅助调用未指定输出上限时使用 2048。预留是保守准入估算，不能当作实测用量或金额消费上限。上游报告合法用量后，预留按输入加输出结算；缓存输入已经包含在输入中。缺失或无效用量保留预留，不能记成零消耗。

上游请求最多存续 10 分钟，数据库并发租约为 11 分钟。API 异常退出留下的租约会自然失效；失败或取消后的未知用量仍占最近一分钟的预算。完成结算按调用 ID 幂等，重复关闭响应流不会重复统计。数据库结算失败保留预留并记录固定错误码，不记录上游诊断正文。

配额拒绝会使原生运行收到 `model_quota_exceeded`；辅助调用继续沿用原有失败处理。修改限额后重启全部 API 副本，避免副本使用不同配置。

## 数据与指标

`model_call` 只记录工作区、运行/会话标识、用途、部署模型名、重试序号、时间、状态和用量，不存储提示词、工具参数、响应正文、上游地址或凭据。工作区删除会清理调用记录，并阻止删除后重新插入。超过七天的记录在后续准入时每次最多清理 128 条；无新调用时不会主动清理，因此不是严格的七天保留上限。

通过现有指标监听器采集下列序列。标签仅含固定用途、结果、Token 类型或工具类别，不使用工作区、运行、模型名称等动态标识。

| 序列 | 含义 |
| --- | --- |
| `multica_model_api_admission_total` | 共享配额允许/拒绝次数 |
| `multica_model_api_attempts_total` | 已结束的上游 HTTP 尝试，包含辅助用途与重试 |
| `multica_model_api_duration_seconds` | 上游请求至流关闭的耗时 |
| `multica_model_api_tokens_total` | 实测输入、输出、缓存输入；缓存为输入子集 |
| `multica_model_api_unknown_usage_total` | 未获得合法用量的尝试 |
| `multica_model_api_retries_total` | SDK 的非首次 HTTP 尝试 |
| `multica_model_api_estimated_cost_usd_total` | 按已有价格表估算的美元费用，不是上游账单 |
| `multica_model_api_unpriced_usage_total` | 有用量但没有已知价格的尝试 |
| `multica_tool_events_total` | 已持久化的工具开始/结果事件，排除重复 daemon 回调 |

`multica_model_api_*` 是模型 HTTP 维度，旧 `multica_llm_*` 是运行上报维度。两者可能描述同一笔执行用量，不能相加作为总消耗。总模型用量使用前者，并同时查看未知用量和未知价格计数。工具事件涵盖所有运行时；开始/结果计数之差不能作为可靠的活动工具数，活动调用应查看运行消息和检查点。

消息批次的去重键绑定运行领取代际、序号、事件类型和工具调用标识，由数据库唯一索引排除重复回调；只有本次实际插入的事件才发布和累计。消息主键继续使用 UUIDv7。迁移前的消息没有去重键，不追溯合并或调整历史统计；指标是进程计数器，不能替代持久化审计记录。

可导入 [Grafana 仪表盘](observability/native-model-dashboard.json)，选择已有 Prometheus 数据源。它分别展示运行、工具事件、模型调用、延迟、预算拒绝和用量。该文件只提供面板配置，没有自动部署监控服务。

本地验收已用 Prometheus 采集开发 API 的指标，并在 Grafana 浏览器中加载全部 10 个面板：数据源查询均为 HTTP 200，无查询或页面错误，运行、工具、模型请求及重试产生了实际序列。本次假模型没有报告用量，因此 Token 和费用面板没有实测消费数据；用量缺失按未知用量记录，不能把空面板解释为零消费。临时监控容器已在验收后停止。

结构化日志用 `call_id` 关联调用记录，包含用途、运行 ID、结果、耗时、重试次数及是否报告用量。标题和后续建议的失败日志仅保留固定诊断，不打印 SDK 错误中的上游地址或私密正文。
