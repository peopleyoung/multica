# Native 执行能力改造计划

本次改造由主智能体完成，参考相邻 deepseek-harness 的作业、输出落盘和中断恢复实现。独立作业服务采用用户确认的独立 Multica 服务方案。

## 实施顺序与验收

| 阶段 | 改造 | 验收条件 |
| --- | --- | --- |
| 一：恢复与作业反馈 | 中断工具组补齐明确的未知结果；不重放旧调用；缩短新作业 ID；错误提示给出恢复方法；完成通知进入持久模型历史 | 恢复后能够检查外部状态，历史和调用标识不变；同一调用不重复执行；不同会话作业保持隔离 |
| 二：日志与文件 | 完整作业日志写入私有文件；按绝对字节偏移读取与搜索；文件分页读取，保留现有小文件读取方式 | 超过内存窗口的早期错误仍可取回；输出有界；路径不可越界；磁盘错误明确可见 |
| 三：独立作业服务 | 独立 Go 服务，令牌隔离、提交幂等、持久状态、分页日志、取消与容量限制；通过现有受控外部服务接入 Native | Native 任务退出及运行时重启不停止服务作业；响应丢失后按提交身份找回；服务重启不重跑未知命令；取消等待进程树结束 |
| 四：验证与交付 | 单元与集成回归、竞态检查、构建和操作文档 | 不调用真实模型、不启动训练、不修改参考仓库；报告实际检查结果及部署状态 |

## 约束

- 未知结果作为未知事实返回模型，不能伪装成失败或成功；只读核验优先，有副作用操作必须先核验外部状态。普通保存仍不能直接把 unknown 改成终态。
- 完成通知在当前执行内送达；跨任务训练由独立服务托管，不用本地作业的轮询代替持久调度。
- 独立服务是受信任执行节点，命令具有其运行账号权限；令牌只配置在服务和智能体环境中。推荐部署到训练主机并绑定内网或回环地址。
- 服务重启时未结算作业标记为 interrupted，不按 PID 杀进程，不自动重放。服务进程自身故障下的训练接管、GPU 队列和分布式调度不属于第一版保证。
- 日志设磁盘配额并明确标记达到上限，禁止用无限制写盘替代内存限制。
- 不自动重启现有守护进程或重新提交真实训练。先完成代码和验证，再选择不影响在途任务的发布窗口。

## 后续能力

持久交互终端、专门 SSH 执行后端、操作系统级沙箱单独迭代；它们不阻塞本次恢复、日志和持久作业交付。浏览器继续通过已配置 MCP 扩展。

## 实现位置

- 一：`server/pkg/agentstate/recovery.go`、`server/internal/daemon/engine/`、`server/internal/daemon/tools/job_notice.go`。未知结果闭合只允许确定的恢复文字，普通保存不能伪造终态。
- 二：`server/internal/daemon/tools/job_log.go`、`file_page.go`。落盘日志保留前缀，内存保留尾部；配额、缺失区间、字节偏移和 UTF-8 分页均明确返回。
- 三：`server/cmd/native-jobs/`、`server/internal/jobservice/`、`server/internal/daemon/tools/persistent_jobs.go`。运行方式、令牌范围和 API 见[独立作业服务说明](native-job-service.zh.md)。
- 四：与实现相邻的恢复、通知、分页、隔离、幂等及重启回归测试；不依赖真实模型和训练环境。发布构建增加 `native-jobs`，systemd 模板不自动安装或启动。
