# 工作区模型配置

工作区所有者和管理员在「设置 → 模型」维护多个兼容 OpenAI Chat Completions 的模型配置，成员在创建或编辑智能体时选择启用模型。模型配置与执行电脑独立，多个智能体可以在同一 Multica Native 运行时上使用不同 API。

## 使用

1. 添加显示名称、API 基础地址（例如 `https://api.example.com/v1`）、上游模型标识和可选 API 密钥。
2. 填写提供方实际支持的上下文、输出、工具参数及工具数量限制，确认支持流式工具调用。图片和 JSON 输出按实际能力启用。
3. 首个模型自动设为默认模型。智能体的「工作区默认」会在下次执行时解析当前默认模型；显式选择的智能体始终引用指定配置。
4. 编辑已有配置时，密钥留空表示保留；勾选移除才会清除密钥。先调整引用该模型的智能体，再禁用或删除模型；删除默认模型前先设置另一个默认模型。

## 存储与调用

- `workspace_model` 保存工作区内的配置身份；不同配置可以使用相同上游模型标识。
- `agent.model` 存储配置 UUID，空值表示工作区默认。未创建工作区模型的部署仍可使用显式环境配置。
- 密钥通过 AES-256-GCM 加密，使用 API 服务已有的 `MULTICA_VCS_SECRET_KEY`。保留此密钥才能恢复数据库中的凭证。HTTP 响应仅返回 `has_api_key`。
- 任务首次读取模型时在 `agent_task_queue.native_model_config` 原子保存配置及加密凭证。并发读取使用首个已提交快照；任务后续推理、压缩、附件能力校验和建议生成均使用该配置。修改配置供后续任务使用。
- 守护进程按活动任务获取模型标识和能力；不获取 API 地址或提供方密钥。API 服务重新验证任务、机器和租约后调用所选模型，共享现有调用配额与审计机制。
- 工作区删除同时清理配置和任务快照，不增加外键。新增索引各自使用独立的并发迁移。

## 验证

- 数据库集成测试覆盖角色权限、密钥加密与留空保留、显式清除、默认模型、引用删除保护、跨工作区选择拒绝。
- 两个 HTTP 模型桩通过实际原生守护进程后端分别验证上游模型与凭证，并验证配置及智能体选择变化不改变已固定任务。
- 前端测试覆盖异常响应、配置保存失败重试、密钥不回显、成员只读、模型选择和设置导航。
- `e2e/workspace-models.spec.ts` 使用 `TestApiClient` 建立并清理独立工作区，在 Chromium 中新增两个模型并分别创建智能体。使用显式 `MULTICA_MODELS_E2E_USERNAME` / `MULTICA_MODELS_E2E_PASSWORD` 执行；指定 `MULTICA_NATIVE_E2E_BINARY` 时启动显式构建的原生守护进程，使用两个模型桩验证各自凭证、模型选择和实际聊天回复，全程不调用真实模型或外部 AI CLI。

## 23000 部署结果

- 镜像版本为 `models-20261107t015131z`，数据库迁移至 593。访问 [模型设置](http://172.16.66.249:23000/yangshuai/settings?tab=models)。
- 本机 `multica-daemon-harness.service` 已切换新版二进制。原工作区的 5 个智能体迁移到同一机器、同一所有者及私有权限的在线 Multica Native；旧运行时保留为离线历史。
- 测试工作区已清理。原数据为 1 个用户、1 个工作区、5 个智能体、5 个议题、22 条任务记录和 2 个聊天会话。工作区尚无真实模型配置，管理员需在页面填写实际 API 地址、模型与密钥。
- `pnpm typecheck` 的 10 项任务、`pnpm lint` 的 7 项任务及 `git diff --check` 通过；lint 仍有现存警告。78 个 Go 包的完整 race 测试通过。前端全量执行中有 2 项 MCP 设置测试在并行负载下失败，其中一项达到 5 秒超时；该文件单独重跑的 29 项全部通过。多模型相关的 25 项共享页面测试及 127 项 API 客户端测试通过。
- 部署后 Chromium 实际完成「添加两个模型 → 分别创建智能体 → 各自发送聊天 → 收到对应模型回复 → 删除测试工作区」。原账号登录、刷新、CSRF 续期、退出和实例 Cookie 隔离复验通过。

- 备份、迁移回执、容器快照、浏览器结果及发布记录位于 `.multica/harness-deploy/models-rollout/`。从功能发布前快照至发布后，仅 Harness 前后端容器发生替换；此前恢复的旧数据库事件按上一条单独记录。
