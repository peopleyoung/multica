# 用户名密码账号迁移

注册和登录使用独立用户名与密码，邮箱为可选联系信息，不发送验证邮件。注册成功后直接建立登录会话。Web、Desktop 和 Mobile 使用同一套账号规则。

## 接口与身份

- `POST /auth/register`：提交 `username`、`password` 和可选 `email`，成功返回 201。
- `POST /auth/login`：提交 `username`、`password`，成功返回 200。
- 成功响应为 `{ token, user }`，同时设置原有登录 cookie。密码与哈希均不进入响应。
- 用户名统一为小写，3–32 位 ASCII 字母、数字、点、下划线或短横线，以字母或数字开头。密码为 12–72 字节，使用 bcrypt 保存。
- `send-code`、`verify-code` 返回 410；旧客户端需要更新。既有 Google OAuth 集成接口保留，新表单使用用户名和密码。

新账号的 `email_verified=false`。联系邮箱不参与可信身份关联，不能领取邮箱邀请或绕过邮箱白名单。已有已验证邮箱和明确绑定用户 ID 的邀请继续使用；新密码用户可通过工作区分享链接加入。

## 部署与旧账号

1. 使用正常部署迁移流程应用 586–588：新增账号字段、建立用户名唯一索引、允许多个账号不填邮箱。并发索引已登记中断重试清理钩子。
2. 同步更新前端与客户端，再启用密码登录。邮箱服务仅用于通知和邀请。
3. 管理员按原用户 UUID 初始化用户名和密码，命令见[账号设置](../../apps/docs/content/docs/auth-setup.zh.mdx)。操作保留 UUID、资料、成员身份和历史，不根据注册时提交的邮箱自动接管旧用户。
4. 开放注册需要 `ALLOW_SIGNUP=true` 且两个邮箱白名单均为空。关闭公开注册时，管理员使用 `account-admin --create --username=alice --password-stdin` 创建账号；可选 `--email` 不会验证地址。

镜像包含 `/app/account-admin`，使用目标部署的 `DATABASE_URL`。密码从标准输入读取；不要把密码放进命令参数。忘记密码时由管理员按 UUID 重置；该操作不会撤销已有 JWT 会话或 PAT。公开部署的认证限流沿用 `REDIS_URL` 和 `RATE_LIMIT_AUTH`；未配置 Redis 时认证限流关闭。

本地 `make up` 使用独立开发库，默认开发用户名为 `multica_dev`。首次配置生成随机密码，保存到 CLI profile 的 `login-password` 文件，权限为 0600；启动输出提供文件位置。停止和重启保留密码，不再配置固定验证码。

## 回退约束

586 的回退会删除用户名、密码哈希和邮箱验证状态，并恢复旧邮箱唯一约束。多个空邮箱会使该约束恢复失败，因此先为无邮箱账号安排互不重复的地址。回退前应保留账号字段备份，并协调使用旧认证方式的服务端与客户端；只回退程序无法恢复密码账号的旧登录方式。
