독립 사용자 이름과 비밀번호로 가입합니다. 이메일은 선택 사항이며 인증 메일을 보내지 않습니다. 가입 후 바로 로그인됩니다.

## 계정 규칙

사용자 이름은 대소문자를 구분하지 않는 3~32자의 ASCII 영문자, 숫자, 점, 밑줄, 하이픈이며 영문자나 숫자로 시작합니다. 비밀번호는 12~72바이트이며 bcrypt 해시로 저장됩니다.

## 기존 계정과 복구

관리자가 기존 사용자 UUID에 사용자 이름과 비밀번호를 설정하면 소속과 기록이 유지됩니다. 이전 이메일로 다시 가입해도 기존 권한을 얻지 못합니다. 이메일 비밀번호 복구는 제공하지 않습니다. 관리자가 같은 명령으로 재설정하며 기존 세션과 PAT는 해지되지 않습니다.

```bash
read -r -s -p 'New password: ' MULTICA_ACCOUNT_PASSWORD
printf '%s' "$MULTICA_ACCOUNT_PASSWORD" | \
  bash scripts/dev-env.sh exec -- go -C server run ./cmd/account-admin \
    --user-id=USER_UUID --username=alice --password-stdin
unset MULTICA_ACCOUNT_PASSWORD
```

백엔드 이미지에도 `/app/account-admin`이 포함됩니다. 위 명령은 관리되는 개발 DB를 사용합니다. 배포 환경에서는 해당 `DATABASE_URL`로 실행하세요. 비밀번호는 표준 입력으로만 읽습니다. 공개 가입이 닫혀 있으면 `--user-id=USER_UUID`를 `--create`로 바꾸어 계정을 만들 수 있습니다. `--email=alice@example.com`은 선택 사항이며 이메일은 미인증 상태로 유지됩니다.

## 가입 제한

ALLOW_SIGNUP=false는 공개 가입을 차단합니다. 확인되지 않은 이메일은 허용 목록이나 이메일 초대의 권한이 될 수 없습니다. 공개 가입을 사용하려면 이메일 허용 목록을 비우세요. 새 사용자는 명시적으로 공유된 링크로 워크스페이스에 참여할 수 있습니다.

## 로그인 유효 기간

HttpOnly 쿠키 세션은 기본 30일이며 계속 사용하면 갱신됩니다. AUTH_TOKEN_TTL로 기간을 조정할 수 있습니다. CLI와 daemon의 PAT 인증은 유지됩니다.

## 이메일 및 이전 클라이언트

Resend/SMTP는 선택적 알림 서비스입니다. 연락처 이메일은 신원이나 초대 권한을 증명하지 않습니다. 이전 send-code 및 verify-code 경로는 HTTP 410을 반환하므로 클라이언트를 업데이트하세요. Google OAuth API는 기존 연동용으로 유지되지만 새 폼은 사용자 이름과 비밀번호를 사용합니다.
