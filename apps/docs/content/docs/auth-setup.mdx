Register with a unique username and password. Email is optional and no verification email is sent. After registration, you are signed in immediately.

## Account rules

Usernames are case-insensitive, 3–32 ASCII letters, digits, dots, underscores or hyphens, beginning with a letter or digit. Passwords must be 12–72 bytes. Passwords are stored as bcrypt hashes.

## Existing accounts and password recovery

Existing users have no password until an administrator assigns a username and password using the existing user UUID. Never register again to claim an old email address: this does not transfer history or workspace membership. There is no email-based password reset; administrators use the same command for recovery. It does not revoke existing sessions or PATs.

```bash
read -r -s -p 'New password: ' MULTICA_ACCOUNT_PASSWORD
printf '%s' "$MULTICA_ACCOUNT_PASSWORD" | \
  bash scripts/dev-env.sh exec -- go -C server run ./cmd/account-admin \
    --user-id=USER_UUID --username=alice --password-stdin
unset MULTICA_ACCOUNT_PASSWORD
```

`account-admin` is also bundled in the backend image (`/app/account-admin`). The command above targets the managed development database. For a deployment, run the bundled command with its `DATABASE_URL`; passwords are read from stdin only. To create an account when public signup is closed, replace `--user-id=USER_UUID` with `--create` (optionally add `--email=alice@example.com`). Contact email remains unverified.

## Signup restrictions

ALLOW_SIGNUP=false disables public registration. Email allowlists and email invitations cannot authorize new password accounts, because contact addresses are unverified. Clear email allowlists for open username registration. Existing members keep their memberships; new users can join through an explicitly shared workspace link.

## Session lifetime

Browser sessions use HttpOnly cookies, with a default 30-day lifetime and sliding renewal. AUTH_TOKEN_TTL adjusts the lifetime. CLI/daemon PAT authentication continues to work.

## Email and older clients

Resend/SMTP are optional notification services. Contact email does not prove identity or grant email invitations. The retired send-code and verify-code endpoints return HTTP 410; older clients must update. Legacy Google OAuth endpoints remain available for existing integrations, but the new login form uses username/password.
