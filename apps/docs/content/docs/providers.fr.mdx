---
title: Modèle du déploiement
---

Multica appelle directement un modèle unique via son API. Installez le daemon Multica sur chaque ordinateur d’exécution ; les CLI IA externes et leurs comptes ne sont plus nécessaires.

Le daemon reçoit les exécutions via une connexion HTTP/WebSocket authentifiée, prépare le répertoire et exécute les outils natifs. Inférence, résumés, titres et suggestions passent par le serveur API et partagent les quotas PostgreSQL. La clé du modèle reste sur le serveur.

Les outils MCP prennent en charge stdio et HTTP/SSE distant selon les autorisations existantes. Stdio nécessite la permission shell. Sampling, resources et prompts ne sont pas exposés. L’historique et les points de contrôle sont conservés sur le serveur ; les skills sont chargés via les outils natifs.

Les messages, pièces jointes et répertoires de projet existants sont conservés. Une session CLI externe ne peut pas reprendre comme point de contrôle natif. Terminez les exécutions actives, migrez les associations, puis ouvrez une nouvelle session native. Aucun retour automatique vers une CLI n’est prévu.
