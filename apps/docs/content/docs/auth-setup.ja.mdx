独立したユーザー名とパスワードで登録します。メールは任意で、確認メールは送信しません。登録後すぐにログインします。

## アカウントの規則

ユーザー名は大文字小文字を区別せず、英数字で始まる3〜32文字のASCII英数字、点、アンダースコア、ハイフンです。パスワードは12〜72バイトで、bcryptハッシュとして保存します。

## 既存アカウントと復旧

管理者が既存ユーザーUUIDにユーザー名とパスワードを設定すると、所属と履歴を維持できます。同じメールで再登録しても既存の権限は取得できません。メールによるパスワード再設定はありません。管理者が同じコマンドで再設定します。既存のセッションとPATは失効しません。

```bash
read -r -s -p 'New password: ' MULTICA_ACCOUNT_PASSWORD
printf '%s' "$MULTICA_ACCOUNT_PASSWORD" | \
  bash scripts/dev-env.sh exec -- go -C server run ./cmd/account-admin \
    --user-id=USER_UUID --username=alice --password-stdin
unset MULTICA_ACCOUNT_PASSWORD
```

バックエンドイメージにも `/app/account-admin` が含まれます。上記のコマンドは管理された開発 DB を使用します。デプロイ先では対応する `DATABASE_URL` で実行してください。パスワードは標準入力からのみ読み込みます。公開登録を無効にしている場合は `--user-id=USER_UUID` を `--create` に置き換えて新規作成できます。`--email=alice@example.com` は任意で、メールは未確認のままです。

## 登録制限

ALLOW_SIGNUP=falseで公開登録を停止します。未確認の連絡先メールは許可リストやメール招待の権限になりません。公開登録にはメール許可リストを空にしてください。新ユーザーは明示的に共有されたリンクでワークスペースに参加できます。

## セッション有効期間

HttpOnly cookieの有効期間は既定で30日、継続利用時に更新されます。AUTH_TOKEN_TTLで変更できます。CLIとdaemonのPAT認証は維持されます。

## メールと旧クライアント

Resend/SMTPは通知用の任意設定です。連絡先メールは本人確認や招待権限に使いません。旧send-codeとverify-codeはHTTP 410を返すため、クライアントを更新してください。Google OAuth APIは既存連携用に維持しますが、新しいフォームはユーザー名とパスワードを使用します。
