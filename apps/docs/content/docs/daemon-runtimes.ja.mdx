---
title: デーモンとランタイム
---

Multica は API 経由でデプロイの単一モデルを直接呼び出します。実行用コンピュータには Multica デーモンをインストールします。外部 AI CLI のインストールやログインは不要です。

デーモンは認証済み HTTP/WebSocket 接続で実行を受け取り、作業ディレクトリとネイティブツールを管理します。推論、要約、タイトル、提案は API サーバーと PostgreSQL の共有クォータを経由し、モデルキーはサーバーに保持されます。

```bash
multica daemon start
multica daemon status
multica daemon logs -f
multica daemon restart
multica daemon stop
```

ランタイム画面で実行用コンピュータを選びます。各コンピュータは Multica Native を登録します。エージェントはデプロイモデルを使用し、任意のモデル指定や CLI プロファイルは拒否されます。

ファイル書き込みとシェルは既定で無効です。必要に応じて `MULTICA_NATIVE_ALLOW_WRITE=true` と `MULTICA_NATIVE_ALLOW_SHELL=true` を個別に設定します。シェルはデーモンユーザーの OS 権限で動作します。隔離にはコンテナ、VM または専用ユーザーを使用してください。

MCP は既存の権限に従い stdio とリモート HTTP/SSE のツールを利用できます。stdio にはシェル権限が必要です。sampling、resources、prompts は公開しません。モデルとツールの履歴とチェックポイントはサーバーに保存され、スキルはネイティブツールで読み込みます。

過去の実行メッセージ、添付ファイル、プロジェクトディレクトリは保持されます。外部 CLI のセッションはネイティブチェックポイントとして再開できません。実行中の処理を完了させてから関連付けを移行し、新しいセッションを開始してください。CLI への自動切り替えはありません。

モデル未設定の場合は API サーバーの設定を管理者に依頼してください。接続エラーは `multica daemon status` と `multica daemon logs -f` で確認します。更新後は `multica daemon restart` を実行します。
