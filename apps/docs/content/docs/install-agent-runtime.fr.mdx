---
title: Connecter le runtime intégré
---

Multica appelle directement un modèle unique via son API. Installez le daemon Multica sur chaque ordinateur d’exécution ; les CLI IA externes et leurs comptes ne sont plus nécessaires.

L’administrateur configure le modèle sur le serveur API. Utilisez l’adresse, la clé et le modèle du déploiement ; les capacités doivent correspondre au modèle réel.

[Environment variables](/environment-variables)

Installez Multica, connectez-vous au déploiement, puis démarrez le daemon :

```bash
multica setup self-host --server-url https://api.example.com --app-url https://app.example.com
multica daemon start
```

Ouvrez Runtimes et choisissez l’ordinateur d’exécution. Chaque ordinateur enregistre Multica Native. Les agents utilisent le modèle du déploiement ; les modèles arbitraires et profils CLI sont refusés.

L’écriture de fichiers et le shell sont désactivés par défaut. Activez séparément `MULTICA_NATIVE_ALLOW_WRITE=true` et `MULTICA_NATIVE_ALLOW_SHELL=true` si nécessaire. Le shell dispose des permissions système de l’utilisateur du daemon. Utilisez un conteneur, une VM ou un utilisateur dédié pour l’isolation.

Si le modèle n’est pas configuré, contactez l’administrateur du serveur API. Pour les erreurs de connexion, consultez `multica daemon status` et `multica daemon logs -f`. Après une mise à jour, lancez `multica daemon restart`.
