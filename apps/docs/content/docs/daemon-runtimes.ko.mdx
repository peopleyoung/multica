---
title: 데몬과 런타임
---

Multica는 API를 통해 배포에 설정된 단일 모델을 직접 호출합니다. 실행 컴퓨터에는 Multica 데몬만 설치하면 됩니다. 외부 AI CLI 설치나 로그인은 필요하지 않습니다.

데몬은 인증된 HTTP/WebSocket 연결로 실행을 받고 작업 디렉터리와 네이티브 도구를 관리합니다. 추론, 요약, 제목, 제안은 API 서버와 PostgreSQL 공유 할당량을 거치며 모델 키는 서버에 보관됩니다.

```bash
multica daemon start
multica daemon status
multica daemon logs -f
multica daemon restart
multica daemon stop
```

런타임 화면에서 실행 컴퓨터를 선택합니다. 각 컴퓨터는 Multica Native를 등록합니다. 에이전트는 배포 모델을 사용하며 임의의 모델 재정의와 CLI 프로필은 거부됩니다.

파일 쓰기와 셸은 기본적으로 비활성화됩니다. 필요에 따라 `MULTICA_NATIVE_ALLOW_WRITE=true`와 `MULTICA_NATIVE_ALLOW_SHELL=true`를 각각 설정하세요. 셸은 데몬 사용자의 OS 권한으로 실행됩니다. 격리가 필요하면 컨테이너, VM 또는 전용 사용자를 사용하세요.

MCP 도구는 기존 권한에 따라 stdio와 원격 HTTP/SSE를 지원합니다. stdio에는 셸 권한이 필요합니다. sampling, resources, prompts는 노출하지 않습니다. 모델·도구 기록과 체크포인트는 서버에 저장되고 skill은 네이티브 도구로 불러옵니다.

기존 실행 메시지, 첨부 파일, 프로젝트 디렉터리는 유지됩니다. 외부 CLI 세션을 네이티브 체크포인트로 재개할 수는 없습니다. 실행 중인 작업을 마친 후 연결을 이전하고 새 네이티브 세션을 시작하세요. CLI로 자동 전환하지 않습니다.

모델이 설정되지 않았다면 관리자에게 API 서버 설정을 요청하세요. 연결 오류는 `multica daemon status`와 `multica daemon logs -f`로 확인합니다. 데몬 업데이트 후 `multica daemon restart`를 실행하세요.
