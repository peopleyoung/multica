Inscrivez-vous avec un nom d’utilisateur unique et un mot de passe. L’e-mail est facultatif et aucun code n’est envoyé. La connexion suit immédiatement l’inscription.

## Règles du compte

Le nom comporte 3 à 32 lettres ASCII, chiffres, points, tirets ou traits de soulignement, commence par une lettre ou un chiffre et ne distingue pas la casse. Le mot de passe comporte 12 à 72 octets et est stocké sous forme de hachage bcrypt.

## Comptes existants et récupération

Un administrateur attribue un nom et un mot de passe à l’UUID existant pour conserver les espaces et l’historique. Réinscrire une ancienne adresse ne transfère aucun accès. Il n’y a pas de récupération par e-mail ; utilisez la même commande administrative. Les sessions et PAT existants ne sont pas révoqués.

```bash
read -r -s -p 'New password: ' MULTICA_ACCOUNT_PASSWORD
printf '%s' "$MULTICA_ACCOUNT_PASSWORD" | \
  bash scripts/dev-env.sh exec -- go -C server run ./cmd/account-admin \
    --user-id=USER_UUID --username=alice --password-stdin
unset MULTICA_ACCOUNT_PASSWORD
```

L'image backend inclut aussi `/app/account-admin`. La commande ci-dessus utilise la base de développement gérée. En déploiement, utilisez le `DATABASE_URL` correspondant ; les mots de passe sont lus uniquement sur l'entrée standard. Si l'inscription publique est fermée, remplacez `--user-id=USER_UUID` par `--create` pour créer un compte. `--email=alice@example.com` est facultatif et reste non vérifié.

## Restrictions d’inscription

ALLOW_SIGNUP=false désactive les inscriptions publiques. Une adresse non vérifiée ne permet pas de bénéficier des listes autorisées ou invitations par e-mail. Videz les listes d’e-mails pour ouvrir les inscriptions. Les nouveaux utilisateurs peuvent rejoindre un espace par un lien partagé explicitement.

## Durée de vie des sessions

Les cookies HttpOnly conservent les sessions 30 jours par défaut, avec renouvellement glissant. AUTH_TOKEN_TTL règle la durée. Les PAT du CLI et du daemon restent valides.

## E-mail et anciens clients

Resend/SMTP sont facultatifs pour les notifications. L’e-mail de contact n’accorde aucun droit d’invitation. Les anciennes routes send-code et verify-code renvoient HTTP 410. Les points de terminaison Google OAuth sont conservés pour les intégrations existantes ; le nouveau formulaire utilise le nom et le mot de passe.
